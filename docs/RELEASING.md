# Releasing Ampwire

Follow this checklist exactly. Anyone with push access to `3zcurdia/ampwire`
can run it; no contributor laptop is required beyond tagging.

## Preconditions

1. CI is green on `main` (`.github/workflows/ci.yml`).
2. The Homebrew tap `3zcurdia/homebrew-tap` exists with a README.
3. The repository secret `HOMEBREW_TAP_TOKEN` is set (fine-grained token,
   Contents: Read and write on the tap only).
4. GitHub Pages is enabled with source **GitHub Actions**.

## Release

1. Bump the version in `Cargo.toml` (e.g. `0.1.0`). Run `cargo check` so
   `Cargo.lock` records the new package version.
2. Move `CHANGELOG.md` entries from `Unreleased` to the new version heading.
3. Commit: `git commit -am "Release vX.Y.Z"`.
4. Tag and push:
   ```sh
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```
5. Watch the **Release** workflow: plan → four local builds → global → host →
   publish-homebrew-formula → announce.
6. Verify the release page: 4 archives + 4 `.sha256` + installer + formula +
   `sha256.sum` + attestations. Verify checksums and attestations (see below).
7. Verify the tap: `brew install 3zcurdia/tap/ampwire`, then `ampwire --version`.
8. Run the install smoke tests in step 8 of plan 11.

## Verification commands

```sh
# Checksums
shasum -a 256 -c ampwire-*.tar.xz.sha256   # macOS
sha256sum -c ampwire-*.tar.xz.sha256        # Linux

# Attestations
gh attestation verify ampwire-*.tar.xz --repo 3zcurdia/ampwire

# Minimum OS floors
otool -l ampwire | grep -A4 LC_BUILD_VERSION   # macOS
objdump -T ampwire | grep GLIBC_               # Linux
```

## Prerelease dry run

Before the first stable tag, do a prerelease:

```sh
# In Cargo.toml: 0.1.0-rc.1 (and cargo check to update Cargo.lock)
git commit -am "Release v0.1.0-rc.1"
git tag v0.1.0-rc.1
git push origin v0.1.0-rc.1
```

The tag version must match the package version. The prerelease is marked as a
GitHub prerelease and, with the default `publish-prereleases = false`, it does
**not** overwrite the Homebrew formula. Fix any pipeline issues, delete the
broken tag/release if needed, then repeat with `0.1.0` / `v0.1.0`.

## Local gates before tagging

```sh
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
dist generate --mode ci --check
```

## Notes

- `release.yml` is generated by cargo-dist; never hand-edit it. Change
  `dist-workspace.toml` and run `dist generate --mode ci`.
- The shell installer installs to `~/.local/bin`.
- No macOS signing/notarization in v1.
- Track the hosted-runner follow-up (step 9 of plan 11) before 2027-04-17.
