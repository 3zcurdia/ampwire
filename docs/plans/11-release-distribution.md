# Plan 11 — Release & distribution (GitHub Releases, curl-to-sh, Pages site)

**Status:** ✅ done — 2026-10-25 (repo side; owner-only setup remains).

Goal: pushing a `vX.Y.Z` tag publishes installable artifacts for every
supported platform, and a new user can install with one command:

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://3zcurdia.github.io/ampwire/install.sh | sh
```

or, on macOS/Linux with Homebrew:

```sh
brew install 3zcurdia/tap/ampwire
```

The same page hosts the install guide, requirements (ALSA on Linux), first-run
instructions, upgrade/uninstall steps and troubleshooting. The release process
must be repeatable, checksum-verified and not depend on a contributor's laptop.

Prerequisites: plan 10 is done. This plan needs no player-code changes beyond
`--version`/`--help`; it does need repository-admin access for the Homebrew tap,
the `HOMEBREW_TAP_TOKEN` secret and GitHub Pages.

## What exists today (audit, 2026-10-25)

| Area | State | Problem / opportunity |
|---|---|---|
| `dist-workspace.toml` | cargo-dist `0.32.0`; four targets; `shell` + `homebrew` installers; `install-path = "CARGO_HOME"` | Upgrade to 0.33.0 (current generated actions and attestation support). 0.32 already picks a native `ubuntu-22.04-arm` runner, so the ARM build is not the problem — the install path and the dead Homebrew entry are. |
| `.github/workflows/release.yml` | Generated by 0.32; runs `dist plan` on PRs and builds on tags | Must be regenerated from `dist-workspace.toml`, never hand-edited. No release has ever been tagged. |
| Homebrew | `homebrew` installer enabled, **no `tap`** and no `publish-jobs` | The formula is only a release asset; `brew install 3zcurdia/tap/ampwire` does not exist. Cargo-dist warns about this. |
| Shell installer | Generated, but installs to `CARGO_HOME` (`~/.cargo/bin`) | Wrong default for people who do not use Rust; `ampwire` is then not on their `PATH`. |
| CLI | `--demo`, `--dump` and positional paths only | No `--version`/`--help`; an installer cannot verify the binary, and a failed load (missing ALSA/glibc) is hard to diagnose. |
| Runtime deps | Linux binary links `libasound.so.2`; builds need `libasound2-dev` | Neither the installer nor the README tells the user what to install if ALSA is missing. |
| Website | None; `docs/` contains plans only | No shareable install page, no `/install.sh`, no Pages deployment. |
| Releases | No tags, no GitHub Releases | The install path is not exercised at all yet. |
| macOS | Unsigned, not notarized | Curl and Homebrew do not set the quarantine attribute, so this is acceptable for v1; a browser-downloaded archive may need `xattr -d com.apple.quarantine`. Signing/notarization is a later option (Apple Developer ID required). |

Useful facts from the code:

- `Cargo.toml` already has `description`, `license = "MIT"`, `repository` and
  `homepage`, which the Homebrew formula uses.
- `Config` lives at `$XDG_CONFIG_HOME/ampwire/config.toml`, falling back to
  `~/.config/ampwire/config.toml` (macOS included).
- `src/main.rs` parses `--dump`, `--demo` and positional load inputs, then calls
  `Config::load()` and enters the TUI. `--version`/`--help` must return before
  that point so the smoke test never opens a sound card or a terminal.
- `Cargo.lock` is committed; release builds are binary-crate builds.

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Release tool | Cargo-dist `0.33.0`, config in `dist-workspace.toml`; generated `release.yml` committed | One source of truth; no hand-maintained release YAML. |
| Targets | `aarch64-apple-darwin`, `x86_64-apple-darwin`, `aarch64-unknown-linux-gnu`, `x86_64-unknown-linux-gnu` | Matches the supported platforms. Windows stays out (untested in the code). |
| Shell install path | `~/.local/bin` | Works without Rust; the generated installer writes `~/.local/bin/env` and appends a source line to `.profile`, `.bashrc`, `.zshrc` and the fish conf. No `sudo`. |
| Canonical command | Pages wrapper: `https://3zcurdia.github.io/ampwire/install.sh` | Short, shareable, and stable even when the release asset name changes. It delegates to the cargo-dist installer. |
| Fallback command | `https://github.com/3zcurdia/ampwire/releases/latest/download/ampwire-installer.sh` | Works if Pages is unavailable; generated and checksum-aware. |
| Homebrew | Tap `3zcurdia/homebrew-tap`, `publish-jobs = ["homebrew"]`, secret `HOMEBREW_TAP_TOKEN` | The only way `brew install …/ampwire` works. If the tap cannot be created, remove `homebrew` from `installers` rather than shipping a dead formula. |
| Site location | Static HTML/CSS/JS in `docs/site/`, deployed as a Pages **artifact** | Keeps internal `docs/plans/` out of the published site and avoids adding a Node/Jekyll build. |
| Site URL | `https://3zcurdia.github.io/ampwire/` | GitHub Pages default. A custom domain (`ampwire.dev`, etc.) is an optional follow-up. |
| Linux baseline | glibc ≥ 2.35 (`ubuntu-22.04` userland) and ALSA runtime (`libasound2`) | Matches the current build runners. Keep native runners for v1; see the follow-up about 2027 runner retirement. |
| macOS signing | Not in v1 | Curl/Homebrew installs avoid quarantine. Document the browser-download caveat; revisit only if users hit Gatekeeper. |
| Supply chain | SHA-256 checksums everywhere + GitHub artifact attestations | Cargo-dist generates checksums and `github-attestations = true` adds provenance. The macOS wrapper adds a `sha256sum` shim because cargo-dist's installer only verifies when that command exists, and macOS ships `shasum` instead. |
| Updates | Re-run the installer / `brew upgrade`; no self-updater in v1 | Keeps the shell installer small. `install-updater = false`. |
| Out of scope | Windows, crates.io, AUR, Nix, apt/rpm repositories, server-side transcoding | Not needed for the first public release; document them as unsupported rather than half-shipping them. |

## Steps

### 0. Owner-only setup (do once, before the first tag)

1. Create the public tap repository `3zcurdia/homebrew-tap` with a README.
2. Create a fine-grained GitHub token with **Contents: Read and write** on that
   tap only, and add it to this repository as the secret `HOMEBREW_TAP_TOKEN`.
3. Enable Pages: repository **Settings → Pages → Build and deployment →
   Source: GitHub Actions**. (Or `gh api -X POST repos/3zcurdia/ampwire/pages
   -f build_type=workflow`; this 409s if Pages is already enabled.)
4. Decide the final URL. Default is
   `https://3zcurdia.github.io/ampwire/`. If a custom domain is chosen, add
   `docs/site/CNAME` and the DNS records; update the install URL in the same
   commit. Do not hardcode a custom domain until it resolves over HTTPS.
5. Set the repository homepage after the first deploy:

   ```sh
   gh repo edit 3zcurdia/ampwire --homepage https://3zcurdia.github.io/ampwire/
   ```

Acceptance: `gh repo view 3zcurdia/homebrew-tap`, the secret is listed by
`gh secret list`, and Pages shows the GitHub Actions source.

### 1. Add `--version` and `--help` before any session starts

In `src/main.rs`, handle both flags immediately after collecting `args`, before
`parse_dump`, `Config::load` and any TUI setup:

```text
ampwire 0.1.0
```

and a short help text covering:

```text
Usage: ampwire [OPTIONS] [PATH|smb://SERVER/SHARE ...]

  --demo             run the mock player with the default layout
  --dump WxH         render one frame and exit
  --frame N          advance the mock clock N frames before --dump
  -V, --version      print the version and exit
  -h, --help         print this help and exit
```

Requirements:

- `--version` and `--help` must exit `0` with piped stdin/stdout and must not
  read the config, open a sound card or enter raw mode.
- Keep the existing `--dump`/`--demo` behavior unchanged.
- Add `tests/cli.rs` using `env!("CARGO_BIN_EXE_ampwire")`:
  `--version` prints exactly `ampwire <CARGO_PKG_VERSION>\n`; `--help` contains
  `Usage:` and exits 0.
- Update the README command list.

Verify:


### 2. Finish the cargo-dist configuration

Edit `dist-workspace.toml` (keep the existing `[profile.dist]` block):

```toml
[workspace]
members = ["cargo:."]

[dist]
cargo-dist-version = "0.33.0"
ci = "github"
installers = ["shell", "homebrew"]
targets = [
  "aarch64-apple-darwin",
  "x86_64-apple-darwin",
  "aarch64-unknown-linux-gnu",
  "x86_64-unknown-linux-gnu",
]
install-path = "~/.local/bin"
install-success-msg = "ampwire installed. Run ampwire --version to verify."
hosting = "github"
install-updater = false
tap = "3zcurdia/homebrew-tap"
publish-jobs = ["homebrew"]
github-attestations = true
pr-run-mode = "plan"

[dist.dependencies.apt]
libasound2-dev = "*"

# Native runners (cargo-dist 0.33 already defaults to the arm runner, but pin
# them so a future dist update cannot silently switch to a cross build).
# `global` runs plan/host/global artifacts; it does not produce user binaries,
# so it can move off the deprecated ubuntu-22.04 immediately.
[dist.github-custom-runners]
global = "ubuntu-24.04"
aarch64-apple-darwin = "macos-15"
x86_64-apple-darwin = "macos-15-intel"
aarch64-unknown-linux-gnu = "ubuntu-22.04-arm"
x86_64-unknown-linux-gnu = "ubuntu-22.04"

[profile.dist]
inherits = "release"
lto = "thin"
```

Then regenerate, never hand-edit the workflow:

```sh
cargo install cargo-dist --locked --version 0.33.0
dist init --yes          # updates the generated CI and keeps this config
dist generate --mode ci --check
```

Validation before committing:

```sh
dist plan --output-format=json > /tmp/ampwire-plan.json
jq -r '.ci.github.artifacts_matrix.include[]
       | "\(.runner)  \(.host)  \(.dist_args)"' /tmp/ampwire-plan.json
```

The matrix must contain exactly the four native builds, no `cargo-zigbuild`:

```text
macos-15          aarch64-apple-darwin       --artifacts=local --target=aarch64-apple-darwin
macos-15-intel    x86_64-apple-darwin        --artifacts=local --target=x86_64-apple-darwin
ubuntu-22.04-arm  aarch64-unknown-linux-gnu  --artifacts=local --target=aarch64-unknown-linux-gnu
ubuntu-22.04      x86_64-unknown-linux-gnu   --artifacts=local --target=x86_64-unknown-linux-gnu
```

This exact config was checked while writing the plan with cargo-dist 0.33.0:
`dist plan` produced those four rows, the Homebrew publish job and an installer
whose install path is `$HOME/.local/bin`.

Also check:

```sh
grep -n 'publish-homebrew-formula\|attestations\|contents: write' .github/workflows/release.yml
grep -n 'brew install 3zcurdia/tap/ampwire' /tmp/ampwire-plan.json
```

Build the global artifacts locally as a smoke test:

```sh
dist build --artifacts=global
sh -n target/distrib/ampwire-installer.sh
grep -n '\.local/bin' target/distrib/ampwire-installer.sh
grep -n 'class Ampwire < Formula\|url "' target/distrib/ampwire.rb | head
grep -n 'depends_on' target/distrib/ampwire.rb || true
```

The formula should have no `depends_on "alsa-lib"` on macOS; see the note below.

Notes:

- **Do not add `[dist.dependencies.homebrew] alsa-lib`.** Cargo-dist's formula
  template emits a single global `depends_on` list for all platforms, so it
  would also pull `alsa-lib` into the macOS formula. Instead, document that
  Linuxbrew users need `brew install alsa-lib` (or the distro package) in the
  site's troubleshooting section.
- `install-path = "~/.local/bin"` is the only place the shell installer writes
  the binary. It creates the directory if needed and never uses `sudo`.
- `github-attestations = true` adds `attestations: write`/`id-token: write` to
  the build jobs; keep the generated workflow intact.

### 4. Write the short installer wrapper (`docs/site/install.sh`)

This is deliberately a thin wrapper around the cargo-dist installer; do not
re-implement architecture detection or archive extraction.

Behavior:

```text
AMPWIRE_VERSION=latest   optional pin, e.g. 0.1.0 (validated: [0-9A-Za-z._-])
--help                   show the variable and the direct GitHub URL
```

Algorithm:

1. `#!/bin/sh`, `set -eu`; no bash-only syntax (test with `dash` and macOS
   `/bin/sh`).
2. Resolve the installer URL:
   - `latest` → `https://github.com/3zcurdia/ampwire/releases/latest/download/ampwire-installer.sh`
   - pinned → `https://github.com/3zcurdia/ampwire/releases/download/v$VERSION/ampwire-installer.sh`
3. Download it to a `mktemp` directory with `curl --proto '=https'
   --tlsv1.2 -LsSf` (or `wget -q`) and run `sh "$tmp/ampwire-installer.sh"`.
4. **Make checksum verification work on macOS.** Cargo-dist's installer only
   verifies the archive when `sha256sum` exists, and macOS ships `shasum`
   instead, so the installer silently says "skipping sha256 checksum
   verification". If `sha256sum` is absent but `shasum` exists, prepend a
   temporary shim to `PATH`:

   ```sh
   mkdir -p "$tmp/bin"
   cat > "$tmp/bin/sha256sum" <<'EOF'
   #!/bin/sh
   exec shasum -a 256 "$@"
   EOF
   chmod +x "$tmp/bin/sha256sum"
   PATH="$tmp/bin:$PATH" sh "$tmp/ampwire-installer.sh"
   ```

   `shasum -a 256 -b` accepts the `-b` flag the installer passes, so the
   shim is transparent. Test on macOS that the output no longer contains
   `skipping sha256 checksum verification`.
5. Post-check `"$HOME/.local/bin/ampwire" --version`. On failure, print the
   captured error plus a targeted hint:
   - `libasound` → install the ALSA runtime (`libasound2`/`libasound2t64` on
     Debian/Ubuntu, `alsa-lib` on Fedora/Arch, `alsa` on openSUSE).
   - `GLIBC_` → the system is older than the glibc 2.35 baseline; use a newer
     distro or build from source.
   - missing binary → show the installer output and the direct release URL.
6. If `$HOME/.local/bin` is not on `PATH`, tell the user to restart the shell or
   `source "$HOME/.local/bin/env"` (the generated installer already added the
   rc-file lines).
7. If `AMPWIRE_VERSION` is pinned, mention that upgrades are manual until the
   pin is removed.
8. No `sudo`; the wrapper writes only its temporary directory. The generated
   installer itself adds the binary, `~/.local/bin/env` and the documented
   rc-file source line. No `eval`, no shell interpolation of untrusted release
   data; quote every path.

Test:

```sh
sh -n docs/site/install.sh
shellcheck -s sh docs/site/install.sh
curl -fsSL http://localhost:8000/install.sh | sh -n
```

Add `shellcheck -s sh docs/site/install.sh` to `.github/workflows/ci.yml` (the
Ubuntu runner has shellcheck; install it in the job if the image drops it).
Also demonstrate the pinned form on the site, noting that the variable must be
set on **`sh`**, not on `curl`:

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://3zcurdia.github.io/ampwire/install.sh \
  | AMPWIRE_VERSION=0.1.0 sh
```

### 5. Build the website in `docs/site/`

Static files only; no Node, Jekyll, external fonts, CDNs, analytics or cookies.
Reuse the existing screenshots from `images/` (staged at deploy time; see step 6).

Suggested structure:

```text
docs/site/
  index.html        hero, install commands, features, screenshots, next steps
  install.html      full guide: requirements, verify, upgrade, uninstall, troubleshooting
  style.css         dark retro/terminal look, responsive, prefers-reduced-motion
  404.html
  .nojekyll
  install.sh        the wrapper from step 4
```

`index.html` content outline:

1. Hero: "Ampwire — Winamp 2's anatomy, a modern hi-fi player in your terminal."
   Screenshot, short feature line (local lossless, Jellyfin, native SMB).
2. Install box, with the exact commands:
   - macOS/Linux: the Pages `curl … | sh` command.
   - Homebrew: `brew install 3zcurdia/tap/ampwire`.
   - "Pin a version" disclosure with `AMPWIRE_VERSION`.
   - "Direct from GitHub" fallback link.
   - Copy buttons via progressive-enhancement JS (`navigator.clipboard` with a
     fallback and an `aria-live` confirmation). The code block remains usable
     with JS disabled.
3. Requirements: macOS (Apple Silicon or Intel) or Linux with glibc ≥ 2.35 and
   ALSA; a real TTY; minimum terminal 40×3; Windows unsupported. Show the
   distro commands for the ALSA runtime. Do not guess the minimum macOS
   version: read it from the released binary's `LC_BUILD_VERSION` (see step 8)
   and state that exact version.
4. First run: `ampwire ~/Music`, `ampwire smb://nas/Music`, `j` for Jellyfin,
   `q` to quit; `ampwire --demo` for a no-audio tour.
5. "Verify the download": checksums (`shasum -a 256 -c` / `sha256sum -c`) and
   `gh attestation verify … --repo 3zcurdia/ampwire`.
6. Link to the README for the full keymap/config and to GitHub Releases.
7. Footer: MIT, repository, issues, latest release.

`install.html` adds:

- Upgrade: re-run the curl command; `brew upgrade ampwire`.
- Uninstall: remove `~/.local/bin/ampwire`; optionally remove the
  `source "$HOME/.local/bin/env"` line from the shell rc; `brew uninstall
  ampwire`; config remains at `~/.config/ampwire/config.toml`.
- Troubleshooting: `command not found` → `source ~/.local/bin/env`; missing
  `libasound.so.2`; glibc too old; Gatekeeper/quarantine for browser-downloaded
  archives; `cannot play 96000 Hz` (no resampling, see README); no audio device;
  terminal too small.
- A short "manual install" table with the four archive names and links to the
  latest release. Do not duplicate the full README.

Accessibility/quality:

- Semantic headings, `<main>`, `<nav>`, one `<h1>` per page, alt text.
- Visible focus styles; code blocks scroll horizontally; copy buttons are
  `<button>` with labels.
- Responsive down to ~360 px; no layout shift (set image width/height).
- Respect `prefers-reduced-motion`; no animation required to use the page.
- `<title>`, meta description, canonical URL, Open Graph/Twitter tags.
- Relative links only within the site; absolute links to GitHub/README.

Local preview:

```sh
scripts/preview-site.sh   # stages site + images in a temp dir, serves :8000
```

The script should copy `docs/site` and `images/*.png` into a `mktemp` directory
(referencing `assets/images/…` from the HTML), serve it with
`python3 -m http.server`, and clean up on exit. Do not write staged images into
the working tree.

### 6. Deploy Pages from `docs/site`

Add `.github/workflows/pages.yml`:

```yaml
name: Pages

on:
  push:
    branches: [main]
    paths:
      - "docs/site/**"
      - "images/**"
      - ".github/workflows/pages.yml"
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v6
      - name: Stage screenshots
        run: |
          mkdir -p docs/site/assets/images
          cp images/*.png docs/site/assets/images/
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: docs/site
      - id: deployment
        uses: actions/deploy-pages@v4
```

Acceptance:

```sh
curl -fsSI https://3zcurdia.github.io/ampwire/ | head
curl -fsSL https://3zcurdia.github.io/ampwire/install.sh | sh -n
```

This deploys an artifact from `docs/site`; it does **not** use GitHub's legacy
"deploy from branch /docs" source. If legacy mode is required instead, move the
site files to the `docs/` root and add a `_config.yml` with `exclude: [plans]`
so the internal plans are not published.

The install command in `index.html`, `README.md` and the wrapper must point at
the same URL. If a custom domain is added, update all three plus the CNAME in
one commit.

### 8. End-to-end verification before the stable release

Run on the first prerelease tag, then again on `v0.1.0`:

| Check | How |
|---|---|
| Release assets | 4 archives + 4 `.sha256` + installer + formula + `sha256.sum` + attestations on the release page |
| Checksums | `shasum -a 256 -c ampwire-…tar.xz.sha256` (macOS) and `sha256sum -c` (Linux) |
| Attestations | `gh attestation verify ampwire-…tar.xz --repo 3zcurdia/ampwire` |
| macOS arm64 | `curl …/install.sh \| sh`; `ampwire --version`; `ampwire --dump 80x24` |
| macOS Intel | same on an Intel runner/machine, or a one-off `macos-15-intel` smoke job |
| Linux x86_64 | Docker `ubuntu:22.04`, `ubuntu:24.04`, `debian:12`, `fedora:latest`: install `libasound2`/`alsa-lib`, run the installer, `ampwire --version`, `ampwire --dump 80x24` |
| Linux arm64 | same on `ubuntu-22.04-arm` (native runner) |
| Homebrew | `brew install 3zcurdia/tap/ampwire`; `ampwire --version`; `brew uninstall ampwire` |
| Site | `curl -I` both pages; copy buttons; mobile width; `sh -n` on the served `install.sh` |
| Clean install | a fresh user/home (or container) with no `~/.cargo`, no prior config; confirm the binary lands in `~/.local/bin` and the PATH hint is accurate |
| Uninstall | documented commands remove the binary; config remains unless explicitly removed |
| Minimum OS | `otool -l ampwire \| grep -A4 LC_BUILD_VERSION` for each macOS archive; `objdump -T ampwire \| grep GLIBC_` for Linux; record the real floors in the site/README |

Also run the local gates:

```sh
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
dist generate --mode ci --check
```

### 9. Hosted runner follow-up (before 2027-04)

`ubuntu-22.04` was deprecated on 2026-09-17 and is scheduled to be unsupported
on 2027-04-17. The v1 pipeline deliberately uses it for the two Linux builds
because it gives a glibc 2.35 baseline and native ALSA builds; the `global`

## Done when

- A `v0.1.0` GitHub Release contains the four archives, checksums, the shell
  installer, the Homebrew formula and attestations.
- The Pages site is live at the chosen URL and the curl command works from a
  clean macOS arm64 machine and a clean Linux x86_64 container.
- `brew install 3zcurdia/tap/ampwire` works (or the Homebrew installer is
  explicitly removed from the config and the site).
- `ampwire --version` and `ampwire --help` exit without opening a sound card or
  a TTY.
- README, site and release notes all show the same install command.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
  `cargo test` and `dist generate --mode ci --check` pass on the tagged commit.
- The release checklist in `docs/RELEASING.md` can be followed by someone who
  was not involved in this plan.

## Assumptions / open decisions

- The repository stays at `3zcurdia/ampwire` and remains public. The Homebrew
  tap is `3zcurdia/homebrew-tap`; if a different owner/name is used, update
  `tap`, the secret instructions and all site commands.
- First public version is `0.1.0`; a `0.1.0-rc.1` dry run is acceptable and
  expected.
- The default Pages URL is `https://3zcurdia.github.io/ampwire/`; a custom
  domain is optional and must be decided before the public announcement.
- The site is hand-written static HTML rather than `oranda`/VitePress: fewer
  moving parts, no Node in CI, and full control of the retro visual style. The
  cost is that README content is not automatically reused; keep the install
  command and requirements in sync manually and link to the README for detail.
- No macOS signing/notarization in v1. Revisit if Gatekeeper reports appear for
  curl/Homebrew installs (which should not be quarantined).
- No self-updater, no `cargo install`, no Windows, no AUR/Nix/apt/rpm packages
  in this plan.
