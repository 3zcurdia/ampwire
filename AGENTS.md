# Ampwire — terminal Winamp 2.0 replica with modern hi-fi playback

Goal: retro Winamp 2.x UI/feel in the terminal (Ratatui), but with real modern
playback: local lossless files + Jellyfin server streaming.

## Toolchain

- Rust edition 2024, managed via `mise` (`mise.toml`: `rust = "latest"`).
- TUI: `ratatui 0.30`. Import crossterm as `ratatui::crossterm` — no direct `crossterm` dependency, so the versions always match. Check the ratatui docs first when touching UI/event code — APIs shift between minors.
- Single binary crate. Entrypoint: `src/main.rs` (runs the TUI; `--demo` and `--dump WxH` are the non-interactive paths).

## Commands

- `cargo run` — run the TUI (must use a real TTY; output is garbage under pipes/CI).
- `cargo check --all-targets` — fastest verification loop.
- `cargo clippy --all-targets -- -D warnings` before finishing.
- `cargo fmt --check` / `cargo fmt` — rustfmt is the formatter, no extra config.
- `cargo test` — 360 tests today (357 run, 3 `#[ignore]`d: a visual dump, the audio-device smoke test, and the real-server Jellyfin smoke). Unit tests live next to the modules (`#[cfg(test)] mod tests`); integration tests and the golden frames live in `tests/`.

## Architecture direction

- Keep audio decode/playback decoupled from the Ratatui render loop (dedicated audio thread/task, message-passing — never block `draw` on I/O or decoding).
- Boundaries today: `player` (`PlayerSnapshot` + `PlayerCommand`; `playlist.rs` owns the track list, `order.rs` the ordered/shuffle permutation, `real.rs` the real player, `mock.rs` the demo/dump player), `audio` (symphonia decode → `rtrb` SPSC ring → cpal output on a dedicated engine thread; `dsp.rs` the volume/balance + EQ stage, `eq.rs` the biquad math), `library` (background file scan + lofty tags over `std::sync::mpsc`), `jellyfin` (plan 08: `mod.rs` the blocking `ureq` client + paged library load on a worker thread, `cache.rs` the rolling temp-dir window on its own downloader thread, `http_source.rs` the seekable HTTP `Range` `MediaSource`, `test_server.rs` the `#[cfg(test)]` mock server), `ui` (Winamp skin: main window, playlist, EQ, theme).
- Audio stack (plan 03): `symphonia` (wav/mp3/flac/m4a: AAC or ALAC) → interleaved `f32` → `rtrb` ring buffer → cpal callback. **Three threads**: UI thread (App) · one engine thread that owns the cpal `Stream` *and* the decoder (on macOS the `Stream` is `!Send`, so it is created/used/dropped only there) · cpal's own callback thread (atomics + ring buffer only — never allocates, locks or touches disk). No resampling: the stream opens at the track's own rate/channels; a device that can't is reported as unplayable.
- The UI only ever reads a `PlayerSnapshot`; changes go `Action → App::dispatch → PlayerCommand` into `app::Backend` — `Mock(Box<MockPlayer>)` for `--demo`/`--dump`/tests, `Real(Box<RealPlayer>)` for real sessions (boxed: plan 08's cache state made `RealPlayer` big) — which talks to the engine thread over `std::sync::mpsc` channels. Disk work (scans) runs on a thread and returns over a channel polled from `App::tick`. Render code never sees either backend.
- Hi-fi matters: preserve lossless/bit-perfect path, avoid resampling or volume normalization unless user opts in. Gapless support is expected.
- No workspace, CI, or lint config yet — don't assume any exists.

## Gotchas

- Ratatui 0.30 requires explicit `Terminal::draw` + crossterm event polling; there is no framework auto-refresh.
- `cpal` is wired up: Linux builds need the ALSA dev headers (`libasound2-dev` on Debian/Ubuntu, `alsa-lib` on Arch); macOS CoreAudio needs no extra setup. The cpal `Stream` is `!Send` on macOS — keep it on the engine thread (`src/audio/engine.rs`).
- Sync (plan 04): the clock is **frames played**, not wall time — the audio callback counts what it really pops into an `AtomicU64` (pausing/buffering freezes it for free), and taps one mono sample per frame into a second small `rtrb` ring. The FFT (`src/audio/analysis.rs`) runs on the UI thread inside `RealPlayer::tick` over that tap — never on the audio thread, which stays atomics-and-ring-buffers only. Seeking reloads the stream at an offset (`Decoder::open_at`); the engine's pause flag survives a `Load`, so every load re-asserts Pause/Resume right after it.
- DSP chain order (plan 06): decode → **EQ** (`Dsp::process_eq`) → spectrum tap → volume/balance (`Dsp::process_gain`) → device. The tap therefore shows the *shaped* signal; both stages run over exactly the frames really popped, never the callback's padding silence.
- Gain (plan 05): `src/audio/dsp.rs` — the UI thread writes volume/balance *targets* into `SharedParams` (three `AtomicU32`s holding `f32::to_bits`, plus an `AtomicBool` for `swap_channels`); the callback's `Dsp` smooths toward them per frame (`cur += (target - cur) * 0.002`, snap at 1e-4 — see the comment on why not 1e-5), applies the gains to content positions, then swaps L/R when asked (reversed-wiring DACs — reorder only, never a value change), **only over the frames really popped** and **after** the spectrum tap. All targets and smoothed gains exactly `1.0` (and swap off) → `process` returns before touching a sample (bit-perfect). `Config.audio` (`volume`, `balance`, `swap_channels`) is restored at session start and saved debounced (500 ms, `App::config_dirty_since`). Device errors name the device (`<name>: cannot play 96000 Hz 2ch`) and the give-up notice keeps that reason.
- EQ (plan 06): `src/audio/eq.rs` — 10 RBJ peaking biquads (Q 1.41, ±12 dB, `f64` state) in series + preamp gain, one filter set per channel; bands at/above `0.45 * sample_rate` are skipped; output hard-clamped to ±1.0 (wrap protection, not a limiter). Control is lock-free: `SharedParams::set_eq` writes gains + enabled, then bumps `eq_version` (Release); `Dsp::process_eq` (Acquire) recomputes coefficients on a bump and bypasses when EQ is off **or flat** — so a flat/on EQ is still bit-perfect. `PlayerCommand::SetEq { enabled, gains: [i8; 11] }` (`gains[0]` = preamp) drives it; `RealPlayer::eq_active` clears the bit-perfect marker only when the EQ is on *and* not flat. `[eq]` (`on`, `preamp`, `bands`) persists with the same debounce as `[audio]`; `auto` and presets remain inert (plans 07/08).
- Jellyfin (plan 08): the API key lives **only** in `jellyfin::Client` and travels only as the `Authorization: MediaBrowser Token="…"` header — never in a URL, notice, `Debug` print or error text (every error is a fixed string or a bare HTTP status; `JellyfinConfig`'s manual `Debug` prints `api_key: "<redacted>"`, and `Config::save` leaves `[jellyfin]` untouched). `j` spawns `jellyfin::spawn_library_load` (worker thread, pages of 500 → `JfMsg::Page/Done/Error` → `App::tick`, which sends `RemoveRemote` once on the first page of each load, then `AppendInOrder`); downloads run on the cache's own downloader thread (`cache.rs`) so Stop/Next stay responsive, `<id>.part` is renamed only when complete (a `.part` is never reported ready, never decoded), and `compute_window` counts *remote* tracks in *play* order (shuffle respected). The cache dir `ampwire-jellyfin-<pid>` (mode `0700`) is removed on drop, stale >24 h siblings swept at startup — the sweep touches only that exact name pattern. The engine owns `HttpRangeSource` for `stream*` (`EngineCmd::LoadRemote`; probe blocks the engine thread, so `EngineEvent::Buffering` precedes it; a `200`-to-`Range` server falls back to one whole-file download). `stream_pure` flips `SharedParams::eq_bypass`, which `Dsp::process_eq` re-reads per call (no version bump) and the bit-perfect marker mirrors; the notice `stream pure: eq bypassed` fires once per session at `Started`.
- `cargo test` never opens a sound card; the end-to-end device test is `#[ignore]`d (`cargo test -- --ignored`, it plays an audible tone).
- `Cargo.lock` is committed (binary crate) — keep it that way.
