# Ampwire — terminal player inspired by Winamp 2, with modern hi-fi playback

Goal: a UI/feel **inspired by Winamp 2**, implemented from scratch for the
terminal (Ratatui) — not a port, clone or replica of Winamp — but with real
modern playback: local lossless files + Jellyfin server streaming + native
SMB shares (`smb://…`, no kernel mount, no `libsmbclient`).

## Toolchain

- Rust edition 2024, managed via `mise` (`mise.toml`: `rust = "latest"`).
- TUI: `ratatui 0.30`. Import crossterm as `ratatui::crossterm` — no direct `crossterm` dependency, so the versions always match. Check the ratatui docs first when touching UI/event code — APIs shift between minors.
- Single binary crate. Entrypoint: `src/main.rs` (runs the TUI; `--demo`, `--dump WxH`, `--version`/`-V` and `--help`/`-h` are the non-interactive paths).

## Commands

- `cargo run` — run the TUI (must use a real TTY; output is garbage under pipes/CI).
- `cargo check --all-targets` — fastest verification loop.
- `cargo clippy --all-targets -- -D warnings` before finishing.
- `cargo fmt --check` / `cargo fmt` — rustfmt is the formatter, no extra config.
- `cargo test` — 496 tests today (481 run, 15 `#[ignore]`d: a visual dump, the three audio-device smoke tests, the real-server Jellyfin smoke, nine real-Samba smokes and the MPRIS session-bus smoke). Unit tests live next to the modules (`#[cfg(test)] mod tests`); integration tests and the golden frames live in `tests/`. Plain `cargo test` opens no sound card and touches no network — every real-server SMB test is `#[ignore]`d and needs `AMPWIRE_SMB_TEST_SERVER`, `…_SHARE` and `…_PATH` (a directory for the walk tests, a file for the playback one), e.g. `cargo test smb_spike -- --ignored --nocapture`.
- Release tooling: `dist plan`, `dist generate --mode ci --check`, `dist build --artifacts=global`. Release config lives in `dist-workspace.toml`; `.github/workflows/release.yml` is generated and must not be hand-edited.

## Architecture direction

- Keep audio decode/playback decoupled from the Ratatui render loop (dedicated audio thread/task, message-passing — never block `draw` on I/O or decoding).
- Boundaries today: `player` (`PlayerSnapshot` + `PlayerCommand`; `playlist.rs` owns the track list (`append_sorted` orders each new batch by `Track::sort_key`, a `SortKey` of album group → disc → track number → `alpha_key`, plan 12), `order.rs` the ordered/shuffle permutation (shuffle edits patch it — `appended`/`removed`/`swapped` — only a toggle, replace or clear reshuffles), `real.rs` the real player, `mock.rs` the demo/dump player), `audio` (symphonia decode → `rtrb` SPSC ring → cpal output on a dedicated engine thread; `dsp.rs` the volume/balance + EQ stage, `eq.rs` the biquad math), `library` (background file scan + lofty tags over `std::sync::mpsc`), `jellyfin` (plan 08: `mod.rs` the blocking `ureq` client + paged library load on a worker thread, `cache.rs` the rolling temp-dir window on its own downloader thread plus the one `download_original` and `create_own_dir` every Jellyfin download uses, `http_source.rs` the seekable HTTP `Range` `MediaSource`, `test_server.rs` the `#[cfg(test)]` mock server), `smb` (plan 10: `mod.rs` the `smb://` parser + `LoadInput`, `SmbClientCfg` (redacted `Debug`) and the engine-owned `SmbSetup`, `scan.rs` the share walk on a worker thread behind a `ShareFs` trait whose tests use an in-memory tree, `cache.rs` the rolling temp-dir window on its own downloader thread, `source.rs` the seekable `SmbFileSource` over a `PositionedFile` backend), `ui` (Winamp skin: main window, playlist, EQ, theme).
- Audio stack (plan 03): `symphonia` (wav/mp3/flac/m4a: AAC or ALAC) → interleaved `f32` → `rtrb` ring buffer → cpal output on a dedicated engine thread. **Three threads for audio**: UI thread (App) · one engine thread that owns the cpal `Stream` *and* the decoder (on macOS the `Stream` is `!Send`, so it is created/used/dropped only there) · cpal's own callback thread (atomics + ring buffer only — never allocates, locks or touches disk). Disk/network work runs off those three, one worker per job: the local scan thread, the Jellyfin pager + downloader, and (plan 10) one `spawn_smb_scan` thread per `smb://` URL plus one SMB downloader — all polled from `App::tick`, all talking `mpsc`. No resampling: the stream opens at the track's own rate/channels; a device that can't is reported as unplayable. Plan 09 added the gapless path (see below) and a device/config cache on the engine thread.
- The UI only ever reads a `PlayerSnapshot`; changes go `Action → App::dispatch → PlayerCommand` into `app::Backend` — `Mock(Box<MockPlayer>)` for `--demo`/`--dump`/tests, `Real(Box<RealPlayer>)` for real sessions (boxed: plan 08's cache state made `RealPlayer` big) — which talks to the engine thread over `std::sync::mpsc` channels. Disk work (scans) runs on a thread and returns over a channel polled from `App::tick`. Render code never sees either backend.
- Desktop integration: `remote.rs` holds the serializable `View` of the session plus `RemoteCommand`; `control.rs` owns the Unix socket (`--status`, `--ctl`, single-instance guard) and `mpris.rs` publishes `org.mpris.MediaPlayer2.ampwire` on Linux through `zbus` (a Linux-only dependency). Both services only read the shared `View` and send commands over one `mpsc` channel that `App::tick` drains before touching the player — they never block a frame, the audio engine or the decoder. A second launch forwards its positional paths and exits; the socket is `0600` under `$XDG_RUNTIME_DIR/ampwire` (or `~/.cache/ampwire`), overridable with `AMPWIRE_CONTROL_SOCKET` and disabled with `AMPWIRE_NO_CONTROL`; MPRIS is skipped when there is no session bus. The MPRIS emitter compares the view every 200 ms and emits `PropertiesChanged`/`Seeked`; metadata is empty when stopped.
- Idle CPU: the run loop draws at ~30 fps only while playing (spectrum/clock), 2 fps paused (blink), 1 fps stopped/under an overlay, 5 fps during a background load. It still wakes every 100 ms to drain remote commands. Idle wake-ups are otherwise zero: the engine thread blocks on its command channel when nothing plays and waits 100 ms while paused, and the control socket blocks in `accept` (`ControlServer::drop` wakes it). `App::dirty` marks out-of-cadence redraws (input, remote command, scan page, theme change); a play/pause/stop transition reschedules via `last_interval`. Do not make input events push `next_frame` forward (that freezes the spectrum).
- Hi-fi matters: preserve lossless/bit-perfect path, avoid resampling or volume normalization unless user opts in. Gapless between same-format tracks is implemented (plan 09). The `bit-perfect` marker is Ampwire's own DSP verdict, and also requires `StreamInfo::f32_exact` (≤ 24-bit or 32-bit float source; 32-bit int / 64-bit float are rounded by the `f32` pipeline); `View`/`--status --json` labels it `bit_perfect_scope: "app"` because PipeWire/Bluetooth can still resample outside Ampwire.
- No workspace; CI lives in `.github/workflows/ci.yml` (fmt, check, clippy, test on Ubuntu and macOS) plus `release.yml` (cargo-dist generated); there is no extra lint config beyond rustfmt/clippy defaults.

## Gotchas

- Ratatui 0.30 requires explicit `Terminal::draw` + crossterm event polling; there is no framework auto-refresh.
- `cpal` is wired up: Linux builds need the ALSA dev headers (`libasound2-dev` on Debian/Ubuntu, `alsa-lib` on Arch); macOS CoreAudio needs no extra setup. The cpal `Stream` is `!Send` on macOS — keep it on the engine thread (`src/audio/engine.rs`).
- Platforms: **Linux and macOS are supported and tested; Windows is untested** (never built, never run — no CI, no WASAPI verification). Treat Windows as unsupported: the device + `supported_output_configs()` cache, the exact-rate-only playback rule (Windows shared-mode devices usually expose only 44.1/48 kHz) and the device names in error notices were written for ALSA/CoreAudio. The POSIX permission bits (`0600` config, `0700` Jellyfin *and* SMB cache dirs) are `cfg(unix)`-guarded, so they compile elsewhere but do nothing.
- Sync (plan 04): the clock is **frames played**, not wall time — the audio callback counts what it really pops (whole frames only, one `read_chunk` per callback: a half frame left by the producer waits in the ring, so an underrun can never rotate the channels) into an `AtomicU64` (pausing/buffering freezes it for free), and taps one mono sample per frame into a second small `rtrb` ring. The FFT (`src/audio/analysis.rs`) runs on the UI thread inside `RealPlayer::analyze`, which `App::run` calls once per frame it draws (not per tick), over that tap — never on the audio thread, which stays atomics-and-ring-buffers only. Seeking reloads the stream at an offset (`Decoder::open_at`); the engine's pause flag survives a `Load`, so every load re-asserts Pause/Resume right after it.
- Gapless (plan 09): `RealPlayer` sends `EngineCmd::Queue { source, start: 0, eq_bypass }` for `order.upcoming(1)` right after every `Started` and every boundary crossing, and re-sends (or `Unqueue`s) on every order change — end of order, a repeat *wrap* and a stopped player queue nothing. The engine pre-opens that decoder on the engine thread (local file, cache path, `HttpRangeSource` — a no-`Range` server queues nothing and keeps the download path — or `QueueSource::Smb`), and at the current decoder's EOF swaps it into the **same** stream/ring/DSP when its rate and channels match (incompatible → not queued → today's `Finished` → UI reopen). The switch records `PlaybackHandle::boundary` (frames pushed) *before* `EngineEvent::Advanced(StreamInfo)`; `RealPlayer::check_boundary` moves `current`/clock base/format only when `played >= boundary` — never when the event arrives (it can precede the audio by the ring's length) — then re-queues the following track. A queued track that fails to open is **held** and sent as `Error` at the drain (the skip path stays unchanged). Every `Load`/`LoadRemote`/`Stop` drops the queue with its stream. The cpal device + `supported_output_configs()` are cached on the engine thread (`Cached<DeviceData>`), invalidated on a device error or a config miss (one re-query retry).
- DSP chain order (plan 06): decode → **EQ** (`Dsp::process_eq`) → spectrum tap → volume/balance (`Dsp::process_gain`) → device. The tap therefore shows the *shaped* signal; both stages run over exactly the frames really popped, never the callback's padding silence.
- Gain (plan 05): `src/audio/dsp.rs` — the UI thread writes volume/balance *targets* into `SharedParams` (three `AtomicU32`s holding `f32::to_bits`, plus an `AtomicBool` for `swap_channels`); the callback's `Dsp` smooths toward them per frame (`cur += (target - cur) * 0.002`, snap at 1e-4 — see the comment on why not 1e-5), applies the gains to content positions, then swaps L/R when asked (reversed-wiring DACs — reorder only, never a value change), **only over the frames really popped** and **after** the spectrum tap. All targets and smoothed gains exactly `1.0` (and swap off) → `process` returns before touching a sample (bit-perfect). `Config.audio` (`volume`, `balance`, `swap_channels`) is restored at session start and saved debounced (500 ms, `App::config_dirty_since`). Device errors name the device (`<name>: cannot play 96000 Hz 2ch`) and the give-up notice keeps that reason.
- EQ (plan 06): `src/audio/eq.rs` — 10 RBJ peaking biquads (Q 1.41, ±12 dB, `f64` state) in series + preamp gain, one filter set per channel; bands at/above `0.45 * sample_rate` are skipped; output hard-clamped to ±1.0 (wrap protection, not a limiter). Control is lock-free: `SharedParams::set_eq` writes gains + enabled, then bumps `eq_version` (Release); `Dsp::process_eq` (Acquire) recomputes coefficients on a bump and bypasses when EQ is off **or flat** — so a flat/on EQ is still bit-perfect. `PlayerCommand::SetEq { enabled, gains: [i8; 11] }` (`gains[0]` = preamp) drives it; `RealPlayer::eq_active` clears the bit-perfect marker only when the EQ is on *and* not flat. `[eq]` (`on`, `preamp`, `bands`) persists with the same debounce as `[audio]`; `auto` and presets remain inert (plans 07/08).
- Jellyfin (plan 08): the API key lives **only** in `jellyfin::Client` and travels only as the `Authorization: MediaBrowser Token="…"` header — never in a URL, notice, `Debug` print or error text (every error is a fixed string or a bare HTTP status; `JellyfinConfig`'s manual `Debug` prints `api_key: "<redacted>"`, and `Config::save` leaves `[jellyfin]` untouched). `j` spawns `jellyfin::spawn_library_load` (worker thread, pages of 500 → `JfMsg::Page/Done/Error` → `App::tick`, which sends `RemoveRemote` once on the first page of each load, then `AppendInOrder`); downloads run on the cache's own downloader thread (`cache.rs`) so Stop/Next stay responsive, `<id>.part` is renamed only when complete (a `.part` is never reported ready, never decoded), and `compute_window` counts *remote* tracks in *play* order (shuffle respected). Server item ids are `jellyfin::ItemId` (validated once in `track_from_item`: ASCII alphanumerics, `-`, `_`, ≤ 64) — the only thing allowed into a URL path or a cache file name. `create_own_dir` makes `ampwire-jellyfin-<pid>` fresh with mode `0700` (an existing entry at that name is removed, never adopted), `.part` files are opened `create_new`; the dir is removed on drop, stale >24 h siblings are swept by `RealPlayer::new` in every mode — the sweep touches only that exact name pattern. The engine owns `HttpRangeSource` for `stream*` (`Engine::spawn(params, Option<StreamSetup>, Option<SmbSetup>)`, `EngineCmd::LoadRemote`; the probe blocks the engine thread, so `EngineEvent::Buffering` precedes it, and its body is reused as the first reader). A `200`-to-`Range` server falls back to one whole-file download on a separate cancellable thread (`PendingDownload`) into the engine's own dir, removed when the engine exits. JSON bodies are capped at 32 MiB; the library walk stops at the total or the first empty page. Track-open failures are `audio::PlayError` (`SeekUnsupported` restarts the track, `Failed(reason)` skips) — never matched by text. Key sources: `AMPWIRE_JELLYFIN_API_KEY` > `api_key_file` > `api_key`; `Config::save` keeps the file's permissions and a parse-error notice never quotes the config text. `stream_pure` flips `SharedParams::eq_bypass`, which `Dsp::process_eq` re-reads per call (no version bump) and the bit-perfect marker mirrors — the UI sets it at every `Load`, and the engine flips it at the gapless boundary for the queued track (plan 09); the notice `stream pure: eq bypassed` fires once per session at `Started`.
- SMB (plan 10): `smb::parse_load_input` turns one argument into `LoadInput::{Local,Smb}` (CLI positionals and the `l`/`a` prompt, mixed freely; a *malformed* `smb://` falls back to the local branch, so the prompt says `not found: smb://…` while the CLI exits 2). **The URL always carries server + share** — so `[smb]` has no `server`/`share` keys (owner decision: the plan's own URL rule makes them unreachable), only credentials, `mode` and the window. The password lives in `SmbClientCfg` (manual `Debug` prints `<redacted>`), resolved as `AMPWIRE_SMB_PASSWORD` > `password_file` (trimmed, relative to the config dir) > `password`, and travels only to `share_connect`; with no `[smb]` section at all every URL connects as **guest**, and a connect failure with no section reports `smb: add [smb] credentials to config.toml`. Guest logins retry the spellings `""` → `/GUEST` → `guest` → `GUEST` (Samba takes `/GUEST`, which the `smb` crate's own tests use); a *configured* account is tried once, alone. One `mpsc` channel carries the local scanner **and** one `spawn_smb_scan` thread per URL: `App::poll_scan` keeps the receiver until `scan_pending` hits 0, the first non-empty `Done` applies the load's mode and every later one appends (a mixed `ampwire ~/Music smb://nas/More` never loses a half), `ScanMsg::Failed { reason }` carries the fixed line of a worker that could not start, and a second load while any runs is `already loading`. `Track::is_jellyfin()` guards the three rules that are Jellyfin's alone (the `j`/`RemoveRemote` reload, the Jellyfin window, `stream_pure`'s bypass); each cache window is `PlayOrder::window` filtered by its own `from_track` (`RemoteRef` or `SmbRef`), so an SMB row never enters the Jellyfin window and the reverse. Cache mode: `ampwire-smb-<pid>` (`0700`; the plan-08 `create_own_dir`/`sweep_stale_dirs` are now prefix-parameterized and shared) is created **lazily on the first SMB track**, files are named `<hash>.<ext>` (hash of the canonical URL — no server/share text ever reaches disk), the 512 MiB cap is refused before a byte is written, `.part` is renamed only when complete, eviction takes everything not wanted, `Drop` = Shutdown + join + `remove_dir_all`, and stale >24 h siblings are swept in every mode by prefix. Stream mode: `EngineCmd::LoadSmb` / `QueueSource::Smb` with engine-owned `SmbSetup` (`[smb] mode = "stream"` only) — the probe blocks the *engine* thread (so `Buffering` precedes it), a streamed session gets the ≈2 s ring through `ring_capacity`, and every failure is a fixed `smb: …` line. Tag reads over the wire cost ~16 round trips per file (~0.7 s at LAN latency — measured, and a bigger read-ahead does not help because the reads are seek-triggered), which is why the URL is announced as `loading… <canonical>` before the first 50-file progress tick. Out of scope: SMB1, DFS (`dfs: false`, so a DFS path errors instead of resolving), Kerberos, symlinks/reparse points (the walk skips them), server transcoding, resampling.
- `cargo test` never opens a sound card; the end-to-end device tests are `#[ignore]`d (`cargo test -- --ignored`, they play audible tones). The MPRIS smoke is also `#[ignore]`d and needs a session bus (`dbus-run-session -- cargo test mpris -- --ignored`).
- MPRIS uses `zbus 5` in `[target.'cfg(target_os = "linux")'.dependencies]`; macOS does not compile `mpris.rs`, so verify Linux changes in a container/VM (`cargo check` alone on macOS will not catch them).
- Control protocol: newline-delimited JSON in `control.rs` (`status`, `ctl`, `open`, `ping`). `status` returns the full `remote::View`; `ctl` accepts play/pause/toggle/stop/next/prev/seek/seek-to/volume/shuffle/repeat/load/quit. `open` is the single-instance forwarding path. Keep the socket owner-only and the request bounded (64 KiB); never trust path strings beyond `parse_load_input` and the same `load_inputs` gate the CLI uses.
- `Cargo.lock` is committed (binary crate) — keep it that way.
